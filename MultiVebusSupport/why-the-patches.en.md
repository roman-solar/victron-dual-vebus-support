# Dual VE.Bus Support for Victron Venus OS: purpose and limitations

Some installations need a system in which the grid is used to charge the battery, while separate inverters continuously supply the loads in standalone mode. During normal operation, there is no direct AC path from the grid to these loads. Grid energy reaches them through double conversion: **AC → DC → AC**.

Combined inverter/chargers of the same type, such as MultiPlus or Quattro, can be used on both the input and output sides. In this arrangement, the grid-connected unit acts as a charger, while the output unit or group of units acts as an inverter. They share a common DC bus with the battery connected to it.

This arrangement can be described as “isolated from direct grid supply”. A more precise name for documentation is **a double-conversion system with a separate charger and inverter**. Its principle of continuously supplying the loads is similar to that of an [online double-conversion UPS](https://www.eaton.com/us/en-us/catalog/backup-power-ups-surge-it-power-distribution/eaton-9px-ups.html).

This configuration addresses three needs, which can occur together:

1. **Stable power quality.** The inverter continuously generates the output voltage and its sinusoidal waveform. Grid voltage dips, elevated voltage and waveform distortion are not passed to the loads through a direct AC connection.
2. **Changing the number of phases.** For example, a single-phase grid connection supplies the charger, while a separate three-phase inverter system supplies three-phase loads. The reverse arrangement is also possible.
3. **Continuous supply during a grid outage.** For a conventional MultiPlus-II connection, Victron [specifies a transfer to inverter operation in less than 20 ms](https://www.victronenergy.com/inverters-chargers/multiplus-ii). Even a brief transition can sometimes be noticeable as flickering lights or a disturbance to sensitive equipment. The voltage also changes from the grid voltage previously passed to the loads to the inverter's configured output voltage, usually 230 V. In a system with a separate charger and inverter, the loads are continuously supplied by the inverter. Loss of the grid therefore requires no source transfer on the load side and causes no voltage step associated with that transfer.

The [Cerbo GX manual, Section 5.1](https://www.victronenergy.com/media/pg/Cerbo_GX/en/connecting-victron-products.html), describes how to connect two independent VE.Bus systems to one GX device: one directly to the built-in VE.Bus port and the other through an MK3-USB interface. Both systems appear in the device list and are included in VRM energy statistics. However, only the directly connected system supplies data for the overview pages. ESS and the standard generator start/stop logic also use the directly connected system.

Control of the second system is explained in [Section 12.3.1 on DVCC](https://www.victronenergy.com/media/pg/Cerbo_GX/en/dvcc---distributed-voltage-and-current-control.html). By default, a unit connected through MK3-USB follows its own configuration. The “Managed battery controls all Multis and Quattros” option allows it to receive the Charge Voltage Limit (CVL), Charge Current Limit (CCL) and Discharge Current Limit (DCL) from the CAN-bus BMS. The total CCL is not divided between inverter/chargers: each receives the full value. When several units charge simultaneously, compliance with the battery's total current limit must therefore be ensured separately.

The documentation does not explain how energy transferred between independent systems through a common DC bus is accounted for. In practice, I found that the power conversion hardware worked, but the displayed live energy flows and historical statistics did not match actual consumption and energy movement. I developed **Dual VE.Bus Support for Victron Venus OS** to correct these calculations.

I developed the current package for an installation with two VE.Bus systems: a single-phase MultiPlus-II charges the battery from the grid and connects to the Cerbo GX through MK3-USB; three Quattros form a three-phase system and connect directly through VE.Bus. The installation also has additional separate Victron energy meters for the grid, generator, all AC loads and the PV inverter. In this system, all loads are on the AC-OUT side.

The package contains four logical fixes:

1. **Excluding charger input power from live consumption.** When the grid charger started charging, its input power was added to the load power. This fix removes that addition when the system is configured as having no loads on the AC-input side.
2. **Accounting for AC-input roles separately.** The standard System Setup settings apply the role of a given input number to both VE.Bus systems. The first Quattro input is used for the generator, while the only MultiPlus-II input is connected to the grid. Assigning the Generator role to input 1 attributed the charger's grid energy to the generator, although the Grid meter also recorded it as grid energy. A separate Generator meter reduced the confusion but did not separate the input roles. The patch assigns the Grid role to the charger's input independently and uses it in historical energy calculations. It does not separate the role settings in the System Setup interface.
3. **Using a meter covering all loads for live readings.** By default, GX allows the readings of a Load meter to be monitored but [does not use them to calculate total consumption](https://www.victronenergy.com/media/pg/Cerbo_GX/en/connecting-victron-products.html). The patch allows such a meter to become the primary source of live consumption power. Measurement is retained when an external bypass supplies the loads around the Quattros. If the meter is disconnected or a required value is unavailable, the standard calculation is used. The feature can be disabled for comparison. This fix does not replace historical Total Consumption with the meter readings: conversion losses and the equipment's own consumption remain part of the overall energy balance.
4. **Correct attribution of energy passing through the DC bus.** If energy supplied by the grid charger matches the inverters' consumption, including losses, it passes through the DC bus to the loads with almost no change in battery charge. The standard statistics represented this transfer as charging the battery from the grid and supplying the loads from the battery. The patch matches energy from different VE.Bus systems within the same logging interval and attributes the matching portion to **Grid: Direct use** and **Consumption: From Grid**. The remaining energy is accounted for as battery charging or discharging.

The four fixes are implemented as patches to three Venus OS files and combined into one package. I tested version **v0.9b4** on the installation described above with **Venus OS v3.79**. Tests covered battery operation, grid supply through the DC bus with charger power above and below load power, switching the charger off, and load measurement during bypass operation. The fixes work correctly in these modes. Testing with active PV generation, generator operation, and simultaneous grid and generator use remains to be done. A separate issue with the direction of the battery animation in Remote Console is not corrected by this package.

The package and its settings are stored in the GX device's persistent storage, which survives Venus OS updates. Compatibility checking and reapplication of the patches are provided for after an update. If compatibility checks fail, installation stops and manual adaptation is required. Actual restoration after an OS update has not yet been tested; a successful patch applicability check alone does not confirm correct calculations on a new version.

Other configurations require a review of the settings and, where necessary, adaptation of the algorithm. For example, external meters may be absent, the Load meter may cover only one branch, or some loads may be connected on the grid side. A branch meter cannot be used as a meter for all loads; where input-side loads exist, their consumption must also be included.

Another example is a combination of VE.Bus and VE.Can inverter/chargers. I tested a system in which a MultiPlus-II acts as the grid charger and a **Multi RS** as the output inverter. The Multi RS connects to GX through [VE.Can](https://www.victronenergy.com/media/pg/Cerbo_GX/en/connecting-victron-products.html), so this is no longer a combination of two VE.Bus systems. I found no description of this particular combination in the official documentation. The power conversion arrangement works, but its control and calculation behaviour depends on how the MultiPlus-II is connected:

- **Directly through VE.Bus.** The MultiPlus-II becomes the primary system, taking precedence over the Multi RS. In my tests, both units received limits and SoC from the BMS, but the loads at the Multi RS output were not included in the overall Load value. Installing a meter with the Load role did not correct this.
- **Through MK3-USB.** The MultiPlus-II becomes secondary. Its grid consumption was not displayed in the Grid value. A separate Grid meter added these readings to the VRM dashboard; making them appear in Remote Console required enabling the Multi RS AC-IN in its configuration. In this combination, the option for BMS control of the secondary MultiPlus-II was absent, and it did not receive the BMS/DVCC limits.

With the MK3-USB connection, starting charging also inflated the Load value: the charger's 1 kW consumption was added to the actual 2 kW load, displaying 3 kW. When loads were configured on both AC input and AC output, Remote Console separated them, while the VRM dashboard displayed a combined value. During charging, the direction of the battery animation in Remote Console disagreed with the Charging state and the correct flow shown in the dashboard.

To correct live consumption in this system, I applied separate changes to Venus OS. Adapting the current package to this system requires checking all the features listed above. In particular, the algorithm for historical accounting of energy passing through the DC bus processes only VE.Bus systems and does not cover the Multi RS.

Before applying this package at another site, the actual energy paths, device roles and meter locations must therefore be compared with the conditions for each fix. The calculations must then be tested in that installation's operating modes.

Implementation details, tested modes and remaining validation work are provided in the [package documentation](GUIDE.md).
